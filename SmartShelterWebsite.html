The Project

Problem & Solution

Thousands of street animals face life-threatening cold each winter. Existing wooden shelters can block wind but cannot generate heat.

❄️

The Problem

Volunteers and NGOs build wooden shelters across the city, but wood alone cannot generate heat. On the coldest nights, animals inside these shelters remain at serious risk of hypothermia: even when a shelter is physically present.

💡

Our Solution

Smart Shelter integrates IoT sensors, automated heating control, and real-time remote monitoring into a single system. Heating turns on automatically when an animal is detected inside and temperature drops below 10°C: no human intervention required.

System Operation

How It Works

Three parallel processes run continuously, powered by two microcontrollers and a cloud server.

1

Sensor Reading

BluePill reads the ToF distance sensor every 50ms via I2C and receives temperature/humidity from SHT40 via UART interrupt. Every 1 second it sends aggregated data to ESP32.

2

Decision Logic

ESP32 (FreeRTOS) checks conditions every 500ms. If temperature < 10°C and animal is inside (distance < 500mm) for 3 consecutive checks: heating turns on via GPIO → transistor → relay chain.

3

Data Upload

ESP32 sends sensor data as JSON over TCP to the Go backend on DigitalOcean (port 5678). The backend serves it via HTTP API (port 8080) to the web interface.

4

Live Video

OV5640 camera captures frames → ESP32 encodes to JPEG → RTSP stream → MediaMTX on DigitalOcean → converted to H.264 via ffmpeg → delivered to browser via WebRTC.

5

Heating Control

GPIO signal → 2N2222A transistor (amplifies) → opto-isolated relay (electrical isolation) → 12V heating elements switch on. Hysteresis: turns off above 12°C.

6

Remote Monitoring

Volunteer opens a browser, types the DigitalOcean IP, and sees live sensor data and video in real time. Available in Georgian and English. Supports up to 4 shelters simultaneously.

Components

Each component was chosen for a specific role in the system. Total cost: 378 GEL.

LilyGo T-SIMCAM
ESP32-S3 + OV5640 camera module. Runs FreeRTOS, handles Wi-Fi, video streaming, heating logic and server communication.
Main controller
STM32F103 BluePill
Reads both sensors and forwards aggregated data to ESP32 every 1 second over UART. Bare-metal, no OS.
Sensor hub
VL53L1X ToF Sensor
Time-of-Flight distance sensor. Detects animal presence if distance < 500mm. Communicates via I2C at address 0x29.
I2C · 50ms poll
SHT40
Temperature and humidity sensor. Internal UART bridge module: sends ASCII readings automatically. Received by BluePill via interrupt.
UART · Interrupt
2N2222A Transistor
NPN transistor. Amplifies the 3.3V GPIO signal from ESP32 to drive the 5V relay coil. R_B = 3.3kΩ base resistor.
Signal amplifier
Opto-isolated Relay
SRD-05VDC. Switches the 12V heating circuit. Optical isolation keeps low-voltage control separate from high-voltage load.
5V coil · 12V switch
Heating Elements
12V/30W flexible polyimide heating strips (×15). Powered directly from 12V supply through the relay contact.
12V · 30W each
DigitalOcean Server
Fixed public IP. Runs Go backend (TCP :5678, HTTP :8080) and MediaMTX for RTSP→WebRTC video conversion.
Go · MediaMTX
Architecture

C4 Model Diagrams

System architecture visualized at three levels of detail: Context, Containers, and Components.

C1: Highest level view: Smart Shelter system and its external actors: the volunteer (observer), the shelter, and the animal (beneficiary).
C2: Control System: Data acquisition → Decision logic → Relay control → Server connection. Data flows left to right with a feedback loop from the heating subsystem.
C2: Web Technologies on DigitalOcean: Go backend (JSON/TCP), MediaMTX (RTSP→WebRTC), and the HTML/JS web interface served over HTTP.
C2: Heating & Environment Monitoring: SHT40 (UART), ToF sensor (I2C), relay (5V coil), and 12V heating elements: all controlled by the Control System via GPIO.
C3: Inside the Control System: BluePill reads sensors, sends data to ESP32 via UART. ESP32 runs decision logic, drives the relay chain (GPIO → 2N2222A → opto-relay), and handles Wi-Fi + camera streaming.
C3: Inside Web Technologies: TCP server (port 5678), logic module, HTTP API (port 8080), MediaMTX RTSP receiver + WebRTC publisher, and three web interface panels: sensor data, video player, and manual control.
